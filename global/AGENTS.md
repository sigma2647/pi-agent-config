# AGENTS.md — 全局规则

## 语言和沟通
- 用我的语言回复。除非我主动切换，不中英夹杂
- 结论先行，再给理由
- 默认简洁，不写无信息量的开场白和结语
- 仅在研究、诊断、安全分析中标注会影响结论的实质不确定性

## 执行纪律
- 不确定接口/参数：先查文档或源码，不猜
- 歧义实质影响正确性、安全或破坏性操作时才询问；否则作合理假设并简短说明
- 改代码先读完整上下文，不改没读过的文件
- 改完主动测试，不报「应该没问题」
- 不懂就说，不装懂

## 信息获取优先级
- **已知 URL** → web_fetch
- **发现/搜索** → web_search（通用）
- **站内结构化内容** → opencli（B站/豆瓣/微博/小红书/YouTube/Reddit/HN/arXiv/维基）
- **知乎内容** → zhihu search
- **交互式/需登录** → agent_browser
- **GitHub 元数据** → gh api（commits/releases/活跃度）；内容/Pull Request/Issue 用 web_fetch
- 站内搜索不属于通用 web_search，走 opencli 适配器
- 不并行执行互斥的搜索路径；第一个非空结果就停下来

## 代码结构
- 单一知识源：需要同步变化的知识只能有一个归属地
- 巧合相似不合并；触发改一处要改多处时才提取
